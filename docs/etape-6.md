# Plan — Étape 6 : presse-papiers live

L'étape 6 synchronise le presse-papiers des ordinateurs : je copie sur le Mac,
je colle sur le PC ou sur le téléphone, sans geste supplémentaire. Le
téléphone reçoit automatiquement mais n'envoie que par la tuile de l'étape 3
(Android interdit la lecture en arrière-plan).

Références : jalon « 6. Presse-papiers live » et tableau « Contraintes par
plateforme » de la [conception](design.md), décisions D15 et D16 de
[`decisions-a-prendre.md`](decisions-a-prendre.md).

**Niveau de détail** : plan de cadrage (D2). Au démarrage, relire contre le
code, vérifier les API de chaque OS sur leur version courante, compléter les
tâches et noter les écarts dans `decisions/`.

**Prérequis** : étapes 3, 4 et 5 (les images passent par les blobs).

## Objectif et périmètre

**Résultat attendu** : je copie une phrase sur le Mac ; une seconde plus tard,
Ctrl+V la colle sur le PC Windows. Je copie un mot de passe depuis mon
gestionnaire : il ne part nulle part.

**Inclus** : surveillance sur macOS et Windows (et Linux X11), texte, liens et
images, anti-boucle, filtres des contenus sensibles, réglages par appareil,
écriture automatique à la réception sur les ordinateurs et (en option) sur
Android.

**Exclus** : copier des fichiers (le glisser-déposer de l'étape 5 suffit),
lecture automatique sur Android, surveillance sous GNOME Wayland (nécessite
une extension GNOME Shell : piste séparée, D16).

## Conception

**Détection des changements**

| OS | Mécanisme | Filtres à respecter |
| --- | --- | --- |
| macOS | Sonder `NSPasteboard.changeCount` toutes les 0,5 s | Types `org.nspasteboard.ConcealedType`, `TransientType`, `AutoGeneratedType` : ignorer. Vérifier les alertes de confidentialité du presse-papiers ajoutées par les versions récentes de macOS |
| Windows | `AddClipboardFormatListener` (message `WM_CLIPBOARDUPDATE`) | Formats `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory = 0`, `CanUploadToCloudClipboard = 0` : ignorer |
| Linux X11 | Extension XFixes (`SelectionNotify`) | `x-kde-passwordManagerHint` : ignorer |
| GNOME Wayland | Non pris en charge | Envoi manuel (raccourci de l'étape 4) |

**Contenu** : nouveau `kind: "clip"` dans le corps chiffré, avec `mime`
(`text/plain`, `text/uri-list`, `image/png`), `clip_id` (ULID) et `sensitive`.
Texte jusqu'à 48 Kio dans le message ; au-delà, et pour les images, un blob de
l'étape 5.

**Anti-boucle** : à l'écriture d'un contenu reçu, l'appli garde son empreinte
SHA-256 et son `clip_id` ; le prochain changement détecté avec la même
empreinte est ignoré. Un contenu n'est jamais renvoyé par un appareil qui l'a
reçu. Anti-rebond de 300 ms pour les applis qui écrivent plusieurs formats à
la suite.

**Réglages par appareil** : envoyer automatiquement (oui/non), recevoir dans
le presse-papiers ou seulement en notification, pause temporaire (icône de la
barre de menu), taille maximale, types autorisés.

**Sensible** : un contenu détecté comme sensible n'est pas envoyé par défaut ;
envoyé à la main, il porte `sensitive: true`, Android l'écrit avec
`EXTRA_IS_SENSITIVE`, et il n'entre pas dans l'historique de l'étape 8.

## Critères de fin

| Scénario | Attendu | Vérifié par |
| --- | --- | --- |
| Copier sur Mac, coller sur Windows | En moins de 2 s | Essai réel |
| Copier depuis un gestionnaire de mots de passe | Rien n'est envoyé | Essai réel sur chaque OS |
| Deux ordinateurs qui reçoivent et réécrivent | Aucune boucle | Test + essai |
| Image copiée | Collable sur l'autre ordinateur | Essai réel |
| Pause | Plus rien ne part tant qu'elle est active | Essai réel |
| Ubuntu sous Wayland | Message clair, envoi manuel possible | Essai réel |
